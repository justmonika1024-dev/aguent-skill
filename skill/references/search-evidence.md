# 搜索词推导与证据处理

## S00：搜索能力预检

当选择 Codex 内置浏览器作为搜索提供方时，额外遵守 [浏览器搜索适配器](browser-search.md)。插件已附加不等于能力已就绪，仍须完成本节规定的真实预检。

AUTO 启动前先确认工具的实际能力，不接受仅由输入声明的 `search_available=true`：

| 能力 | 合格结果 | 用途 |
|---|---|---|
| `SEARCH_INDEX` | 返回查询对应的标题、URL、摘要和错误状态 | 发现候选；摘要默认不是正文证据 |
| `SOURCE_FETCH` | 返回指定 URL 的连续正文块及可定位信息 | 严格变式证据 |
| `SEARCH_WITH_CONTENT` | 一次调用同时返回 URL、标题和来源抽取正文 | 可同时满足以上两项 |

必须至少具备 `SEARCH_INDEX`，且具备 `SOURCE_FETCH` 或 `SEARCH_WITH_CONTENT`，AUTO 才进入 O02。MANUAL_SEED 可以先由 O01 接收种子，但在进入任何真实搜索节点前也必须完成 S00。否则输出 `ENVIRONMENT_BLOCKED`；这不表示原梗失败，不消耗业务候选或模板轮次。不得用裸 `curl` 是否能访问某搜索引擎来冒充已具备稳定搜索工具。

记录提供方、能力、预检结果和限制。验证码、登录页、风控页、DNS 错误与超时属于 `PROVIDER_UNAVAILABLE`；正常响应但没有相关内容属于 `NO_RELEVANT_RESULT`，两者不得混淆。允许浏览器使用已有登录态和正常 Cookie，但不得主动读取或导出会话秘密。

## O02-O05：从候选钩子核验完整原梗

AUTO 不从“中文网络梗、热门句式、改编文案”一类宽泛查询开始。主管先基于自身知识提出 3～5 个具体既有梗钩子；模型记忆中的“完整版”仍只是待核验假设。每个候选包含：

- 钩子文字、疑似完整版本及模型记忆置信度；
- 可承载动作或事件的可能位置；
- 至少一条具体疑似真实套改原句，或存在套改家族的可验证理由；
- 一条让 `agu` 保持受事者的最小映射草图；它只用于适配性筛选，不是候选产物；
- 与 Skill 示例、正式梗标题及本轮放弃方向的排除检查。

显式 `STRICT_SLOT` 仍要求两条疑似变式通过 `lead_shape_check`：保留同一固定骨架并可由连续槽位替换解释。`AUTO_ROUTE` 不在 O02 提前猜严格模板，只要求疑似改编保留足以核验的原梗辨识锚点，待 V05 区分槽位替换与宏观节奏变式。

显式 `STRICT_SLOT` 的映射草图仍要求无需联动修改量词、尾句或另一槽位；`AUTO_ROUTE` 可以把“需要少量连贯改写”留给结构路由，但不能把自由另写故事当适配性。按“完整边界可核验性、真实套改可能性、凿agu适配性、固定辨识度”选一个候选进入 O03。

O03 先安排边界查询：钩子精确匹配，并组合 `原文/完整版/完整台词/改编` 或疑似结尾。O04 打开来源正文，O05 按 [完整原梗单元](complete-meme-unit.md) 输出边界对象。`VERIFIED` 后，变式查询必须包含完整参照、两个相隔固定锚点，或一条具体疑似变式。禁止用纯类别查询占用业务预算。

## 首批变式侦察与结构路由

运行环境允许隔离 Codex CLI 会话时，本节搜索按 [精简搜索执行与会话交接](compact-search-execution.md) 拆成短生命周期 worker，并由程序裁剪成精简包；主管不得重新载入全量网页正文。证据定义和 V01-V06 流转不因拆会话改变。

目标是从完整参照出发找到真实改编，不预设最终模式。按信息增益组合查询：

1. 完整参照精确匹配 + `改编/二创/变体/表情包/评论`；
2. 两个相隔的高辨识固定片段分别加引号，中间不写假想槽位；
3. 稀有固定片段 + 可能聚合 UGC 的来源词，如 `site:bilibili.com`、贴吧、知乎回答；
4. 已知出处或场景词 + 原句锚点，用于消除同名噪声；
5. 若搜索结果暴露真实异写或一条真实变式，用其原样值做追加查询。

不要在看到变式前先让模型猜完整模板并排列大量臆测槽位值。长段可以用开场与结尾、开场与中段转折等相隔锚点召回，但抽取时保存变式的完整可见文本，不只摘命中的一句。

V05 对每条逐字正文作双层分类：

- `STRICT_VARIANT`：完整单元可由共同固定骨架与连续槽位替换逐字重建；
- `RHYTHM_VARIANT`：保留开场及至少两个相隔辨识锚点或同等宏观节奏，但存在结构性增删，不能诚实地作为严格槽位证据；
- `REPOST_OR_NOISE`：转载、释义、只借一句开场或无关文本；
- `UNCERTAIN`：正文或边界不可核验。

每条 V04/V05 记录必须包含本轮唯一的 `variant_id`、`verbatim_text`、`classification`、`matched_version_ref`、`observed_boundary_start`、`observed_boundary_end`、`evidence_refs` 和 `classification_reason`。`matched_version_ref` 必须引用 O05 的 `versions[].version_ref`；无法归属时标 `UNCERTAIN`，不能参与路由。

V06 的 AUTO_ROUTE 结果：

- `ROUTE_STRICT_SLOT`：至少 1 条来自可读正文的非重复 `STRICT_VARIANT` 与完整参照共享高辨识固定骨架，且两者能由同一最窄模板逐字重建；后续 T09 仍须达到原句之外至少 2 条非重复严格变式、2 个内容组且高价值位置有真实差异覆盖的收敛门槛；
- `ROUTE_LONG_FORM`：至少 1 条来自可读正文、边界足以判断的 `RHYTHM_VARIANT`，保留完整参照的开场以及两个相隔分句/段落的辨识锚点或同等“开场—转折—收束”节奏，但单一严格模板不能逐字重建；L02 继续补证并标置信度；
- `NEED_MORE_EVIDENCE`：证据混合或过少，继续不同信息增益查询；
- `RESELECT_VERSION`：另一支系证据表明当前完整参照选择不当，回到 O05 重选版本；
- `UNSUITABLE`：只有转载/噪声，或两类结构均无正证据；AUTO 换候选。

禁止使用“STRICT_VARIANT 不足”作为 `ROUTE_LONG_FORM` 的唯一理由。同一候选经过至少两个不同信息增益查询仍只有无关正常响应时切换候选；提供方不可用不算内容失败。

V06 只统计 `matched_version_ref == selected_version_ref` 的证据；其他支系不参与当前路由。当前版本同时具有合格 STRICT 与 RHYTHM 证据时输出 `NEED_MORE_EVIDENCE`，先补搜辨别主结构，不用多数票或固定字符占比拍板。若证据表明应采用另一版本，输出 `RESELECT_VERSION`，回到 O05 更新 `selected_version_ref`、`complete_reference_text`、`selection_reason` 与 `boundary_change_log`，随后重新执行 V01-V06；禁止在当前 STRICT 分支失败后就地切换 LONG_FORM。

`CONTROLLED_REWRITE` 不改变 V/T 阶段的证据定义或数量门槛。C02 生成的候选只能记录为生成推断，不得回写为 `STRICT_VARIANT`、模板绑定或后续搜索的已观察槽位值。

## 扩展搜索（`STRICT_SLOT`）

由程序从模板生成查询计划，主管判断优先级：

- 组合相邻固定片段；
- 固定片段 + 已观察槽位值；
- 原始槽位值与新槽位值交叉；
- 同一来源或同一聚合页面继续深挖；
- 针对尚未发生变化的槽位选择最可能提供反例的查询。

每条查询应回答一个问题：找到新槽位值、验证边界、寻找反例、确认重复约束，或提高来源独立性。

在扩搜前先对已接受变式做程序化差异覆盖审计，再由主管标出对凿agu生成有价值的位置。已有 2 条严格变式但内容组不足，或动作/事件、受事者、施事者、关键判断等高价值位置从未真实变化时，可用至多 2 个短、句法匹配的 `RETRIEVAL_HYPOTHESIS` 启动一次定向 micro-worker；只有 1 条严格变式时不进入低收益 micro。检索假设只能用于组成查询，来源正文逐字核验前不是观察值、模板槽位或生成参考。

## 查询推导实例

原梗候选：`你们不要再打了啦`。

原梗核验：

```text
你们不要再打了啦 梗 原句
"你们不要再打了啦" 表情包
不要再打了啦 练舞室 梗
```

首批变式：

```text
"你们不要再打了啦" 改编
"你们不要再打了啦" 二创
"你们不要再" "了啦" 梗
"住手 你们不要再" 改编
```

观察到 `泥萌不要再打了啦`、`你们不要再跳了` 后：

```text
"你们不要再跳了啦"
"你们不要再吵了啦"
"你们不要再" "了啦"
"不要再打了啦" "不要再跳了"
```

发现完整边界可能包含 `住手` 后：

```text
"住手 你们不要再肝了"
"住手 你们不要再卷了"
"住脚 你们不要再跳了啦"
"住手 你们不要再" "了啦"
```

这里的搜索词来自：模型对场景的先验记忆、原句固定锚点、搜索结果中已出现的真实值，以及用于找反例的推测值。推测值只能构成查询，不能成为证据。

## 正文抽取

- 保存 URL、标题、查询、请求 ID、原始正文或连续正文块、时间及费用。
- 一个页面**明确聚合多条独立例句**时才逐条拆分，例如换行列表、编号、引号或稳定分隔符已给出条目边界；每条保留页内连续引文和位置，同页多条可算多条变式，但来源独立性只算一个内容组。不得从一个带前缀、后缀或续写的单句中裁掉外围文字，只为“救出”内部匹配子串；这种候选整体按前后缀增加或续写拒绝，除非来源另有一处把内部文本作为独立条目逐字列出。
- 搜索摘要只能作为候选线索；能抓到来源正文时优先以正文为准。
- 先做字符规范化以辅助比较，同时永久保留原文；繁简、标点、空格和常见异写不能虚增变式数。

## 严格验证（`STRICT_SLOT` 的 V05 子判定及 T 扩搜）

对每条候选依次检查：

1. 引文是否逐字存在；
2. 是否不是原句复述；
3. 固定骨架是否连续且具有辨识度；
4. 差异是否能由槽位替换解释，而非增删或释义；
5. 是否与已经接受的标准化文本重复；
6. 是否提供新的槽位值、边界或来源信息。

输出 `ACCEPTED / REJECTED / UNCERTAIN`，并给出原子理由。`UNCERTAIN` 不进入模板主证据。
