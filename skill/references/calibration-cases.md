# 正反校准案例

这些案例用于校准判断，不是网络证据库。标注“生成”的文本只能作为生成参考。

## 原梗完整边界校准

以下是边界示意，不是新的网络证据：

| 搜索钩子 | 应核验的闭合单元 | 判断 |
|---|---|---|
| `我怀疑你在开车` | `我怀疑你在开车，但我没有证据` | 后半句兑现转折和笑点，不能截断 |
| `大胆妖孽` | `大胆妖孽，我一眼就看出你不是人` | 只有呵斥没有识别结论，不闭合 |
| `你说的对，但是《原神》` | 选择一个来源明确、含后续介绍与结尾收束的完整传播支系 | 开头可能独立传播，也可能只是长段钩子；依据真实变式支系选择并保留备选版本 |

长短不决定模式：较长文本若同族可由同一模板逐字重建，仍用 `STRICT_SLOT`；较短文本若真实改编只保留宏观节奏且有结构增删，可用 `LONG_FORM`。没有真实宏观改编正证据时，不能因严格验证失败而切到长梗。

## 正向：最小替换保住原梗

原梗：`你们不要再打了啦`，后续搜索还暴露了包含 `住手` 的完整边界以及 `跳/吵/卷/肝` 等动作槽位线索。

生成结果：

```text
住手！你们不要再凿agu了啦！
```

优点：`凿agu` 正好占据动作槽位，施事者是“你们”，固定节奏和情绪完整，只做了一次关键替换。这是首选风格。

同类结构校准：

```text
你有本事凿agu，你有本事开门啊！
扶我起来，我还能凿agu。
```

两者都把 `凿agu` 放入原本允许动作/事件的槽位，没有另写解释。

这类原梗已经可以严格回填，必须保持 `generation_mode=STRICT_FILL`；不能为了制造更复杂的笑点降级到受控局部改写。

## 正向：严格槽位不适配时的一次共指联动

以下均是生成校准，不是网络变式证据。只有完整原梗、真实严格变式、模板与槽位契约均已确认后才可使用。

原梗：

```text
真是令人愉悦啊，五条悟，我大概一生都不会忘了你吧。
```

受控改写：

```text
真是令人愉悦啊，agu，我大概一生都不会忘了凿你吧。
```

实体槽只做 `五条悟 → agu`，再在同一共指链上做 `你 → 凿你`；主语“我”仍是施事者，其他固定锚点逐字保留。

原梗：

```text
我不是针对你，我是说在座的各位都是垃圾。
```

受控改写：

```text
我不是针对agu，我是说在座的各位都得凿他。
```

实体槽 `你 → agu` 与局部判断 `都是垃圾 → 都得凿他` 共同完成一次共指联动；两个分句、对照关系和核心锚点不变。

## 反向：受控改写越界

对“真是令人愉悦啊……”案例，下列方向应拒绝：

```text
真是令人愉悦啊，agu，高程群的人每天都来凿你，我这一生都不会忘记这场盛宴。
```

它新增背景和第二个笑点，同时改写时间强度及结尾，不是一处必要的共指谓词联动。若一个候选需要新增分句、改写多个无关谓词或重排原句，C03 必须淘汰；不能通过改称 `LONG_FORM` 绕过。

## 正向：重复槽位与角色约束

证据族：`你才sorry，你全家都sorry` / `你才傲娇，你全家都傲娇`。

模板：

```text
{S2}才{S1}，{S2}全家都{S1}
```

关键点：同一槽位多处出现必须同值；不能为方便生成把两处拆成互不相关的槽位。

## 正向：语义事件按槽位内部句法实现

若事件槽的证据值具有“承受者＋的＋遭遇事件”结构，生成时应保留这种内部关系，而不是机械直填一个动宾短语。此时 `agu的被凿` 与 `凿agu` 都只替换同一个槽位，不能按字符数把前者判为“改动更多”；应由句法贴合度、通顺度和幽默度决定选择。没有连续出现字符串 `凿agu` 不代表语义缺失，只要 agu 明确是“凿”的受事者即可。

## 正向：证据要求拆簇

原梗：`无所谓，我会出手`。

变式中若同时出现 `无所谓，我会逃跑`、`无所谓，我开摆`、`无所谓，某人会出手`，应拆为：

```text
无所谓，我会{S1}
无所谓，我{S1}
无所谓，{S1}会出手
```

不要用过宽的 `无所谓，{S1}` 吞掉全部证据。

## 反向：模板对但回填脱模

原梗：`大胆妖孽，我一眼就看出你不是人`。

可用假设模板：

```text
大胆{被呵斥对象}，我一眼就看出你不是{表面身份}
```

曾出现的失败生成包括把后半句改成“你就是要凿agu”、增加“不是在凿石头，你是在凿agu”、或改成“凿痕正是你留下的”。这些句子可能通顺，却改写了固定文本和判断逻辑，不是模板回填。

正确结论未必是硬塞 `凿agu`；若槽位只能容纳被呵斥对象和身份名词，应该在 G01 判定适配性低，换原梗优于脱模创作。

## 反向：把事件解释满

原梗族：`你说得对，但是《原神》是由米哈游自主研发的一款开放世界冒险游戏……`

问题模式：为了让每个槽位都与 `凿agu` 有关，把研发方、主题和后续描述全部写成长篇解释，句子失去原文节奏。

较合理的探索方向是：主题槽位可填事件名词化的“凿agu”，研发方映射施事者，后续描述维持与“开放世界冒险游戏”相近的长度；但此案例历史上回填评价不稳定，不应当作已验证的金标准。

## 人工反馈所确认的关键修正

- `agu` 是动作受事者，不是一个待替换的抽象主题。
- 必须按已提取模板替换，不能只借原梗气氛自由发挥。
- 后续槽位长度应接近原文，长解释会降低辨识度。
- 候选差异不等于质量；至少保留一条最小替换，并优先比较它。
- 结构合法仍可能语言笨重；通顺、节奏和中文搭配必须单独审查。
